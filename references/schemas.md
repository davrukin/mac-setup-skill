# File formats

All files live in `data/` (override with the `MAC_SETUP_DATA` environment variable).

## Contents
- presets.yaml
- inventory.json
- Grouping JSON (`audit --categorization`)
- web_recommendations.json
- recommendations/<preset>.json

## presets.yaml

```yaml
presets:
  developer:
    description: Software engineering tools
    source: audit:heuristic      # audit | audit:heuristic | audit:ai | audit:assistant | import:<where>
    taps: [someone/tools]
    brews: [git, jq, someone/tools/mytool]
    casks: [visual-studio-code, iterm2]
    mas:                          # Mac App Store; id is the numeric App Store id
      - {name: Xcode, id: 497799835}
    vscode: [ms-python.python]
```

All list keys are optional. Presets whose `source` starts with `audit` are regenerated by the next audit; any other preset is kept. Earlier versions of this tool wrote only `description`, `casks`, `brews`; those files still load.

## inventory.json

```json
{
  "generated": "2026-10-26",
  "taps": [], "brews": [], "casks": [],
  "mas": [{"name": "Xcode", "id": 497799835}],
  "vscode": [],
  "adopted_casks": ["google-chrome"],     // manual apps matched to a real cask (already merged into casks)
  "unmatched_apps": ["Some Tool"],        // no cask exists: install by hand
  "mas_apps_seen": ["Xcode"],
  "apple_apps_skipped": 12
}
```

## Grouping JSON (`audit --categorization FILE`)

An assistant-written grouping. Group names are free-form; each becomes a preset. Use item names exactly as they appear in `inventory.json`. `mas` accepts names or numeric ids. Items not in the inventory are dropped with a warning.

```json
{
  "developer": {"description": "Android and backend work", "casks": ["android-studio"], "brews": ["git", "jq"], "vscode": ["ms-python.python"]},
  "photo":     {"description": "Film scanning and RAW workflow", "casks": ["darktable"], "brews": ["exiftool"], "mas": ["Pixelmator Pro"]}
}
```

## game_choices.json (`audit --game`)

`{"categories": {"developer": "d", "common": "c", "hobby": "h"}, "choices": {"casks:figma": "common", "mas:497799835": "developer", "brews:jq": "skip"}}`. `categories` maps each category to its hotkey (empty string for none), including ones created in the game. Choice keys are `<kind>:<name>` (App Store apps use the numeric id); values are a category name or `skip` (everything only). Items missing from the file are unsorted and stay in `current_system` only.

## manual_apps.json (`manual` command)

Written by the assistant from `unmatched_apps` in inventory.json: `{"generated", "classified_by", "entries": [{"apps": ["App A", "App B"], "category": "photography", "source": "vendor|setapp|steam|gog|app-store|chrome|cask|covered|bundled|discontinued|it-managed|unknown", "url"?, "verified"?: true|false, "cask"?, "note"?}]}`. `apps` are names exactly as in `unmatched_apps`; related apps share an entry. `category` is one of the user's game categories, `not_needed` or `unsure`. `verified` is true only when a search confirmed the URL. `cask` names a working Homebrew cask that the name matcher missed. `setup.sh manual` renders `manual-installs.md` and lists unclassified apps.

## web_recommendations.json

Written by an assistant after online research; read by `recommend.py` (default path `data/web_recommendations.json`).

```json
{
  "generated": "2026-10-26",
  "items": [
    {
      "name": "ripgrep",
      "type": "brew",                       // "brew" | "cask" ("unknown" is resolved against Homebrew)
      "tier": 1,                            // optional 1-3; omit to let source count decide
      "reason": "Fast code search; named in most developer tool roundups",
      "categories": ["developer"],          // optional
      "sources": ["https://example.com/list-a", "https://example.com/list-b"]
    }
  ]
}
```

Tier when omitted: 3 or more independent sources = tier 1, two = tier 2, one = tier 3.

## recommendations/<preset>.json

Same three buckets as the original tool, plus bookkeeping keys that start with an underscore:

```json
{
  "tier_1_very_useful":     [{"name": "ripgrep", "type": "brew", "reason": "...", "sources": ["seed"], "verified": true}],
  "tier_2_nice_to_have":    [],
  "tier_3_could_be_useful": [],
  "_dropped_unverified": ["made-up-app (cask)"],
  "_roles": ["developer", "essentials"]
}
```

`verified` is true/false when Homebrew could check the name, `null` when it could not (no Homebrew, or a tap-qualified name).
